# Surveys Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a survey subsystem: reusable question templates with branching, survey instances sent to a snapshotted audience with invitation and reminder emails, a respondent flow with autosave, and admin reporting with cross-survey trends.

**Architecture:** Six new Postgres tables (templates, questions, surveys, recipients, responses, answers) with rows for answers and jsonb only for per-question config/visibility. Pure, unit-tested domain logic in `src/lib/surveys/` (question registry, branching evaluator, validation, lock rules, reporting math). Server-side lib modules for audience, lifecycle, respondent, reminders. Thin `actions.ts` files under `src/app/dashboard/manage-surveys/` and `src/app/dashboard/surveys/` delegate to lib. Email through the existing notification dispatcher; reminders through a daily Vercel cron.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Drizzle ORM + Postgres, better-auth, shadcn/ui, Tailwind v4, recharts, Vitest (unit + integration), Biome.

**Spec:** `docs/superpowers/specs/2026-09-19-surveys-design.md` (read it first; every decision below argues from it).

## Global Constraints

- pnpm only. Biome: 4-space indent, no semicolons, no trailing commas. Run `pnpm lint` last before every commit (CI fails on unused imports).
- `src/lib`, `src/database`, `src/config` never import `next/*`, `@/next/*`, `@/app/*`, `@/components/*`. Lib code that acts for a user takes `userId`.
- Every exported server action calls `requireSession()` and `requirePermission(...)` (or `requireAdmin()`); `pnpm check-authz` fails otherwise. Wrap in `withAction`, return `ok()`/`fail()`.
- Integration tests: `*.integration.test.ts`, colocated, use `createUserWithRoles` from `src/test/session.ts` and factories from `src/test/factories.ts`; Postmark is mocked (`vi.mocked(sendBatchEmails)`), role checks are real. Unauthorized results are exactly `{ status: false, message: "Unauthorized." }`.
- Unit tests: `*.test.ts`, the db import throws, so pure modules must not import `@/database/db`.
- Schema: `serial` ids, `timestamp().defaultNow().notNull()`, snake_case columns, indexes named `<table>_<cols>_idx`, jsonb columns typed with `$type<>()`. New tables only in this feature. Generate the migration with `DOTENV_CONFIG_PATH=.env.local npx drizzle-kit generate` and rename it to `0021_surveys.sql` (update `migrations/meta/_journal.json` tag to match); `pnpm check-migrations` must pass.
- Commit at the end of every task; push to `origin main` at the end of every phase after `pnpm lint && pnpm check-types && pnpm check-authz && pnpm test` are green. Commit trailer lines are in the session's system reminder.
- Model guidance for subagents: pure logic and integration-heavy tasks → opus; UI-only tasks that follow an existing component closely and small wiring tasks → sonnet.

```ts
// src/lib/surveys/question-types.ts — client-safe registry
import type { AnswerValue, SurveyQuestionConfig, SurveyQuestionDef, SurveyQuestionType } from "./types"

export interface AnswerColumns { value_bool: boolean | null; value_number: number | null; value_text: string | null; value_options: string[] | null }

export interface QuestionTypeDef {
    label: string
    description: string
    hasAnswer: boolean
    defaultConfig(): SurveyQuestionConfig
    /** null when valid, else a human-readable error */
    validateConfig(config: SurveyQuestionConfig): string | null
    /** null when valid; value has already passed isEmpty() === false */
    validateAnswer(question: SurveyQuestionDef, value: AnswerValue): string | null
    toColumns(value: AnswerValue): AnswerColumns
    fromColumns(columns: AnswerColumns): AnswerValue | null
}
export const QUESTION_TYPE_DEFS: Record<SurveyQuestionType, QuestionTypeDef>
export function isEmptyAnswer(value: AnswerValue | null | undefined): boolean   // undefined/null/""/[] → true; false and 0 are NOT empty
export function optionsOf(config: SurveyQuestionConfig): SurveyOption[]         // [] for types without options
export function generateOptionKey(): string                                     // "opt_" + 8 random base36 chars
```

Validation rules to implement (these are the unit tests):
- `rating`: integers, `min < max`, `max - min <= 10`, `min >= 0`; answer must be an integer within `[min, max]`.
- `likert`: options must be exactly `LIKERT_OPTIONS` keys in order (labels may differ); answer is one of the keys.
- `single_choice`: 2..maxOptions options, unique non-empty keys, non-empty labels; answer is a string key that exists.
- `multi_choice`: same option rules; `0 <= minSelections <= maxSelections <= options.length` when set; answer is a string[] of unique existing keys within the bounds.
- `text`: variant short|long; `maxLength` in `1..maxTextAnswerLength`; answer is a string, trimmed length ≤ maxLength (default `maxTextAnswerLength`).
- `ranking`: 2..maxOptions options; answer is a string[] that is a permutation of all option keys.
- `yes_no`: answer is boolean. `section`: `hasAnswer: false`, `validateAnswer` returns "This question does not take an answer."
- `toColumns`/`fromColumns`: yes_no ↔ value_bool; rating ↔ value_number; text ↔ value_text; likert/single_choice ↔ value_options (single-element array); multi_choice/ranking ↔ value_options.

```ts
export interface SubmissionValidation { visible: Set<number>; cleaned: AnswerMap; errors: Record<number, string> }
```
